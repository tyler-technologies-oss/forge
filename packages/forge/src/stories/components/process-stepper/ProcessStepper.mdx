Process steppers show where a user is within a multi-step process. Additional details and subtasks
may be presented directly within each step.

<Canvas of={ProcessStepperStories.Demo} />

## Orientation

Process steppers are vertical by default, which gives each step room for details and
interactive content. Set `orientation` to `horizontal` for compact, progress-oriented
processes where steps are distributed evenly across the available width.

<Canvas of={ProcessStepperStories.Horizontal} />

### Responsive Layout

A horizontal stepper has no room for legible labels side by side in a small container — four steps
in a 360px container leaves roughly 48px each. Below 600px of available width, a horizontal stepper
therefore lays its steps out vertically, which gives every label and its details the width it needs.
The progress line stays visible as a vertical rail.

The switch is driven by the stepper's own width rather than the viewport, so a stepper inside a
narrow column adapts too. The `orientation` attribute is unchanged; the read-only `compact` property
reports whether the compact layout is active. A stepper that is already vertical never changes.

## Step States

Set the `state` property on each step to communicate its position in the process. The state controls
the marker treatment:

| State                | Marker                                 |
| -------------------- | -------------------------------------- |
| `not-started`        | Dashed outline                         |
| `current`            | Filled with a check icon, and the step is the current step in the process |
| `in-progress`        | Partially filled                       |
| `completed`          | Filled with a check icon               |
| `critical`           | Error outline with an exclamation icon |

<Canvas of={ProcessStepperStories.States} />

### Progress Track

The progress track appears to the left of a vertical process stepper or above a horizontal process
stepper, indicating the user's current position in the process. Each step up to and including the
step with the "current" state has its portion of the track filled. If no step is marked current the
track remains entirely unfilled.

### Disabled Steps

Set the `disabled` property on a step to dim it and prevent interaction.

<Canvas of={ProcessStepperStories.Disabled} />

### Support Text

Use the `support text` slot for additional context under the label, such as `Optional` or a short
description of of the error on an invalid step.

### Custom Markers

To replace a generated marker entirely, provide your own content in the step's `marker` slot.

## Step Numbers

Markers render only an icon by default. Set `numbered` on the stepper to display each step's number
inside its marker. Steps that render a filled icon, such as completed and critical steps, continue
to show the icon rather than a number.

## Titles

The stepper does not render a title of its own. Place a heading at the appropriate level for the
surrounding page before the stepper, and reference it with `aria-labelledby` so the list is named
after it:

```html
<h3 id="record-progress-title" class="forge-typography--subheading1">Record progress</h3>
<forge-process-stepper aria-labelledby="record-progress-title">...</forge-process-stepper>
```

## Interactive Steps

Every step renders a button in its shadow DOM, with the slotted label as its content. Set `href` on a
step to render a link instead.

```html
<!-- Performs an action -->
<forge-process-step state="current">Suspension</forge-process-step>

<!-- Navigates -->
<forge-process-step state="completed" href="/cart">Cart</forge-process-step>
```

Use `href` when activating the step navigates, so it keeps the browser behaviour users expect from
a link, and leave it unset when the step performs an action in place. Set `disabled` to dim the step
and prevent interaction. A disabled link is rendered without its `href` and with `aria-disabled="true"`.

Only the default slot is placed in the button or link, so a button in the `details` slot does not
make the step itself interactive.

Activating a step dispatches a `forge-process-step-select` event from the step and a
`change` event from the stepper. Read the activated step from the stepper's `selectedStep`
property:

```typescript
stepper.addEventListener('change', (event: Event) => {
  const { selectedStep } = event.target as ProcessStepperComponent;
});
```

## Read Only

Set `readonly` on the stepper to use it as a non-interactive indicator of progress. Steps in a
read-only stepper render only their label, without a button or link, so they are not focusable and
cannot be activated. `href` and `disabled` have no visible effect on a read-only step.

## Accessibility

Process steppers are rendered as semantic lists with `role="list"` on the stepper and
`role="listitem"` on each step. Each step reports its position and the number of steps, and
`aria-current="step"` when its state is `current`. State markers are decorative and marked
`aria-hidden="true"`.

When a stepper only shows part of a longer process, set `aria-posinset` and `aria-setsize` on each
step. They take precedence over the step's position in the DOM for the accessibility tree, the
number shown in the marker, and progress announcements.

Each step is a single list item. The interactive area of a step is a native button or link, and a
step's details content is a sibling of it rather than nested inside it, so interactive content keeps
its own semantics.

### Progress Announcements

Steps announce the position a process has moved to through the shared Forge live announcer, for
example "Step 3 of 5: Internal review". A step announces whenever its state is set to `current`,
including when a consumer advances the process programmatically, and stays silent on the initial
render so a screen reader is not interrupted when the page loads.

### Best Practices

- Because the marker is decorative, never rely on it alone to communicate state. Give steps whose
  state is not obvious from the label supporting text in the `details` slot
- Set `href` when a step navigates and leave it unset when it acts, so it carries the
  right semantics and keyboard behaviour for what it does
- Provide a heading alongside the process stepper and asssociate it with the stepper using
  `aria-labelledby`
- Interactive content placed in the `details` slot keeps its own semantics
  and focus behavior, so label it as you would anywhere else
