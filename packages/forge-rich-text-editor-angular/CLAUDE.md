# Forge Angular Rich Text Editor Adapter

Typed Angular component proxies and `NgModule`s around `@tylertech/forge-rich-text-editor`'s custom
elements.

## Purpose

Same reason `@tylertech/forge-angular` exists: `CUSTOM_ELEMENTS_SCHEMA` lets templates reference
`forge-*` tags but loses type-checking on inputs and outputs and requires registering each element
by hand. Each proxy sets values via the JS property API and its module calls the element's
`define*Component()` function.

`@tylertech/forge-rich-text-editor` is a **peerDependency**, as are `@angular/common` and
`@angular/core` (`>=20.0.0 < 23.0.0`).

## Architecture — generated, and committed

- `src/lib/<component>/` — one folder per element, each with a generated `*.component.ts` proxy,
  `*.module.ts` and `index.ts` barrel. **Generated by
  `pnpm run --filter @tylertech/forge-rich-text-editor-angular generate-proxies` — do not hand-edit,
  regenerate instead.** Unlike the React adapter, this output **is committed**, matching
  `@tylertech/forge-angular`.
- `src/lib/rte.module.ts` — generated aggregate `ForgeRteModule` importing and re-exporting every
  proxy module, for consumers who want the whole surface in one import.
- `scripts/generate-proxies.mjs` — config only; the file to edit when the surface changes.
- `src/public-api.ts` — the `ng-packagr` entry file.
- `src/dev/` — an Angular CLI demo on **localhost:3462**. Not published.

### Why the generator runs twice

`generateAngularAdapter` delegates to `@tylertech/forge-schematics`' `custom-elements` schematic,
which accepts a **single `importPath`**. The editor package exports its core elements from the root
and its `forge-rte-*` features from `./features`, so the generator runs **one schematic pass per
entry point** and merges the results. The log line reports the pass count.

The schematic also emits no directory barrels and never touches the public API barrel (a TODO in its
own source), so `generateAngularAdapter` writes both plus the aggregate module. Leaving that to hand
maintenance is how the rich text editor proxies in `@tylertech/forge-extended-angular` ended up
generated but unreachable.

If `@tylertech/forge-schematics` gains import-path overrides, the two-pass workaround may become
unnecessary — check `generate-proxies.mjs` against it before assuming it still needs both passes.

## Do not remove the `sass` and `vite` devDependencies

**This package's declarations are the fix for a deadlock, not incidental.** `sass` is an optional
peer of vite, and vite a peer of vitest. A package declaring `vite` or `@angular/build` without a
matching `sass` forks a second vitest instance, and pnpm dedupes one shared `@angular/build` whose
vitest link then points at the wrong instance — so the `unit-test` builder runs on a different
vitest runtime than the test project and the suite deadlocks after reporting exactly one spec file.

This surfaced as `@tylertech/forge-angular`'s suite hanging, not this package's. Both `sass` and
`vite` are declared here from the **catalog**, and must stay on the same catalog entries as every
other vite-consuming package.

If that suite ever hangs again, compare the vitest instance reached from the project against the one
reached from `@angular/build` — they must resolve to the same `.pnpm` directory.

## Commands

```bash
pnpm run --filter @tylertech/forge-rich-text-editor-angular build   # regenerate + ng-packagr
pnpm run --filter @tylertech/forge-rich-text-editor-angular test    # @angular/build:unit-test
pnpm run --filter @tylertech/forge-rich-text-editor-angular dev     # demo at localhost:3462
```

## Testing

Uses Angular's `@angular/build:unit-test` builder with `runner: "vitest"`, in real Chromium
configured through `angular.json` rather than `vitest.config.ts` — the builder owns test execution
and does not support arbitrary Vitest config. Real-browser mode is required: jsdom's
`ElementInternals` / `showModal` / `matchMedia` gaps break Forge's custom elements.

Smoke tests only, matching `@tylertech/forge-angular`: one test validating the generated proxy
pattern is worth more than one per generated wrapper.
