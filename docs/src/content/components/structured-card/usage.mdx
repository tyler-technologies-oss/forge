## Overview

The structured card is a pre-configured card layout optimized for common patterns in Tyler Cloud applications. Its slot-based architecture provides designated areas for a title, header actions, body content, and footer buttons, so teams build consistent card UIs without hand-assembling the same header and footer structure every time. It's ideal for table containers and self-contained content sections that need their own actions.

## Usage

`forge-structured-card` lays out a <a href={`${import.meta.env.BASE_URL}components/card/usage/`}>card</a> through named slots — `before-title`, `title`, `header-actions`, `after-header-actions`, `body`, `footer-start`, `footer-secondary-action`, and `footer-primary-action` — plus `heading-level` to set the title's semantic level and `body-spacing` to remove body padding for edge-to-edge content. Every slot is optional, and the header and footer hide when nothing is slotted into them. Use it when a card needs a header, body, and footer; for a card that only groups content with no header or footer, use a plain `forge-card` instead.

## Tables

Set `body-spacing="none"` (or the `bodySpacing` property) for full-width content like a table. It removes the body padding and the footer's bottom padding so the content runs edge to edge. Put a paginator in `footer-primary-action`.

<Example
  description="A structured card containing a table, with refresh and download icon buttons in the header and a paginator in the footer."
  blockUrl="https://forge.tylerdev.io/blocks/v1/components/structured-card/with-table/with-table.html"
/>

Use `footer-start` for buttons or controls that belong at the start of the footer, opposite the paginator.
