## Overview

A count card highlights a single number or metric alongside an icon and a short label, so people can scan key figures at a glance. It's built for dashboards and summary views, where several count cards sit side by side to summarize the state of a system.

Count cards can carry supporting details, such as a trend badge, a progress meter, or a sparkline, and a card-level action menu.

## Usage

`forge-count-card` is built from named slots (`icon`, `label`, `header-end`, `action`, `count`, `count-end`, `body`, and `full-width`) plus `theme` to apply semantic color and `no-border` to remove the border. Every slot is optional, but include at least an icon and a count, and use the same slots across the cards on a page so they stay aligned in a grid. Put a `forge-icon-button` in `action`, not `header-end`, so its 48px touch target aligns correctly. Use a count card for a single metric; for a general container with a header, body, and footer, use a <a href={`${import.meta.env.BASE_URL}components/structured-card/usage/`}>structured card</a> instead.

## Basic usage

Slot an icon, a label, and a count. Add a badge to `header-end` for supporting context.

## Multiple cards

Count cards work well in a grid to build a dashboard-style summary.

<Example description="Four count cards in a responsive grid." />

## With full width

Use the `full-width` slot for content that spans the card's width below the count, such as a sparkline or progress indicator.

<Example description="A count card with a sparkline spanning its full width." />

## Additional body content

Use the `body` slot to add supporting content below the count, such as a progress meter or a last-updated time.

<Example description="A count card with a trend badge, a meter, and a last-updated line in the body." />

## With menu

Use the `action` slot to add an icon button that opens a card-level menu.

<Example description="A count card with an icon button that opens an options menu." />

## Themes

Set `theme` to `primary`, `secondary`, `tertiary`, `success`, `error`, `warning`, `info`, or `info-secondary` to apply semantic color. The default is `none`.
