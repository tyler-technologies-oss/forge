## Usage

`forge-time-picker` wraps a child <a href={`${import.meta.env.BASE_URL}components/text-field/usage/`}>text field</a> and adds a dropdown of selectable time options, through `use24HourTime`, `min`/`max`/`step`, `restrictedTimes`, `masked`, and `allowInput`. Use it when a person is entering a specific time; for a time range, place two time pickers side by side. Reach for a <a href={`${import.meta.env.BASE_URL}components/select/usage/`}>select</a> instead when the choice is really a vague description ("now", "in 30 minutes") rather than a specific time, or a plain <a href={`${import.meta.env.BASE_URL}components/text-field/usage/`}>text field</a> instead when the value isn't a time at all.

## Working with values

<InlineMessage theme="warning" title="Always use 24-hour format in code">
  Regardless of the display format shown to the user, every programmatic read or write of `value` — and the `change` event — uses 24-hour time (e.g. `"15:30"`). This keeps the format locale-independent. Set values through `forge-time-picker` itself, never the wrapped `<input>` (the input only takes cosmetic attributes like `placeholder`). If the field needs to be `required` or `invalid`, set that on the embedded `forge-text-field`, not on `forge-time-picker`.

  ```js
  const picker = document.querySelector("forge-time-picker");
  picker.value = "15:30"; // always 24-hour, even if use24HourTime is false
  picker.addEventListener("change", () => console.log(picker.value)); // also 24-hour
  ```
</InlineMessage>
