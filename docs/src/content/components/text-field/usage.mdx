## Usage

`forge-text-field` wraps a child `<input>` or `<textarea>` and an optional `<label>`, handling layout and state through `variant`, `theme`, `shape`, `density`, `label-position`, `invalid`, `required`, `optional`, and `disabled`. For a fixed set of choices, reach for a <a href={`${import.meta.env.BASE_URL}components/select/usage/`}>select</a> or <a href={`${import.meta.env.BASE_URL}components/autocomplete/usage/`}>autocomplete</a> instead; for freeform, removable entries like tags or recipients, use a <a href={`${import.meta.env.BASE_URL}components/chip-field/usage/`}>chip field</a>.

## Label position

Set `label-position` to control where the label sits relative to the input: `inset` (the default) floats it inside the field, `block-start` places it above, and `inline-start` places it beside the field.

## Helper text and validation

Slot support text in the `helper-text` slot, set `required` for a required field, and set `invalid` to swap in error text describing the fix.

<InlineMessage theme="warning" title="Set required on both elements">
  `required` on `forge-text-field` only shows the required-field indicator — it's presentational. Native form validation and accessibility come from `required` on the nested `<input>`. Set both, or validation silently breaks.

  ```html
  <forge-text-field required>
    <input required />
  </forge-text-field>
  ```
</InlineMessage>
