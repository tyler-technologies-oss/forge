## Usage

`forge-radio` lets a user select a single option from a visible set; group related radios so only one can be checked at a time, either informally by sharing a `name` or formally inside a `forge-radio-group`. It's one of three selection controls — reach for a <a href={`${import.meta.env.BASE_URL}components/checkbox/usage/`}>checkbox</a> when more than one option can be selected, or a <a href={`${import.meta.env.BASE_URL}components/switch/usage/`}>switch</a> to turn a single item on or off. When screen space is tight or the set is long, a <a href={`${import.meta.env.BASE_URL}components/select/usage/`}>select</a> compacts the same choice into a closed control.

## Grouping without forge-radio-group

`forge-radio-group` isn't required — radios sharing a `name` already form an implicit group:

```html
<forge-radio name="default">Option 1</forge-radio>
<forge-radio name="default">Option 2</forge-radio>
```

For a custom layout that still needs to be interpreted as a group, set `role="radiogroup"` on a plain ancestor element instead:

```html
<div role="radiogroup" aria-label="Choose an option">
  <forge-radio name="default">Option 1</forge-radio>
  <forge-radio name="default">Option 2</forge-radio>
</div>
```

## Disabled and read-only

`disabled` radios can't be focused; `readonly` radios can be focused but not changed.
