## Usage

<InlineMessage theme="warning" title="Deprecated">
  forge-chip-field is deprecated and will be removed in a future release.
  forge-text-field and forge-select are the intended replacement path once they
  gain equivalent functionality — avoid building new usage on chip field.
</InlineMessage>

`forge-chip-field` wraps a slotted `<input>` and shares the same field frame as a <a href={`${import.meta.env.BASE_URL}components/text-field/usage/`}>text field</a> (`variant`, `theme`, `shape`, `density`, `label-position`, `invalid`, `required`, `disabled`) plus its own `add-on-blur`. The field itself doesn't create chips — it fires `forge-chip-field-member-added` and `forge-chip-field-member-removed`, and the app appends or removes a <a href={`${import.meta.env.BASE_URL}components/chip/usage/`}>chip</a> with `slot="member"` in response. Use it for freeform, removable entries like tags or recipients; for a single value, use a plain text field, and for entries chosen from a known list, pair it with <a href={`${import.meta.env.BASE_URL}components/autocomplete/usage/`}>autocomplete</a> instead of accepting arbitrary text.

      "Don't display static, non-interactive values as chips — use badges instead.",
    ]}
  />
</Rules>

## Adding chips

Type a value and press Enter to fire `forge-chip-field-member-added` with the entered text; append a `forge-chip` with `slot="member"` in response, and remove it on `forge-chip-field-member-removed`.
